# 小田园 · v9

一个**双击即玩**的单文件种田小游戏（等距视角、纯前端、无依赖、无后端）。源码拆成多个文件，由构建脚本组装成单文件产物。

```
farm.html         ← 普通拼接产物（可读、带分节注释）★ 直接双击这个
farm.min.html     ← 压缩产物（esbuild minify，体积约 40%）
build.js          ← 组装脚本（两份产物 + 语法校验）
build.manifest.json ← 拼接清单（顺序即声明顺序）
src/              ← 源码：index.html 模板 + css/ + js/
tools/            ← 构建期的校验工具（冒烟测试 / 真实渲染 / 像素校验）
legacy/           ← v8.0 原始单文件备份
```

## 仓库里有什么 / 没有什么

**入库**：`src/`（源码）、`build.js` + `build.manifest.json`（构建）、`tools/`（测试与工具）、`deploy/`（部署脚本 + 排行榜服务）、`legacy/`、`README.md`。

**不入库**（跑命令生成，已写进 `.gitignore`）：
- `farm.html` / `farm.min.html` —— `node build.js`
- `src/dev-bundle.js` / `src/dev-bundle.css` —— 源码版拼接产物，`node build.js` 会顺手生成，也可以只跑 `node tools/devbundle.js`
- `dist/` —— 打包出来的 zip/tar.gz（发给别人 / 传服务器用）

## 直接跑源码（不构建）

`src/index.html` **可以直接打开**（双击 file:// 或访问本地服务器的 `/dev`），它引的是两个拼接产物：

```
src/dev-bundle.css   ← tools/devbundle.js 生成
src/dev-bundle.js    ← 同上（源码按 build.manifest.json 顺序拼成一个 IIFE）
```

```bash
node tools/serve.js 8123     # 然后开 http://127.0.0.1:8123/dev
#   /dev 每次请求都会按需重新拼接 dev-bundle.*，改完源码刷新即可，不用构建
node tools/devbundle.js      # 不走服务器时手动重新生成（改完源码后跑一次，再刷新浏览器）
node tools/devcheck.js       # 源码版自检：真的按浏览器方式加载 src/index.html，13 项断言
```

**为什么不能直接给 `src/index.html` 挂 45 个 `<script src="js/xxx.js">`？** 两个原因，都踩过：

1. `src/index.html` 是**模板**：只有 `/*@INJECT_CSS@*/` 与 `/*@INJECT_JS@*/` 两个占位符，构建才往里注入内容。直接打开等于「没有 CSS、没有 JS」→ 白屏。
2. 就算把文件都挂上也不行：`src/js/*.js` 是**拼进同一个 IIFE** 才有意义的（`00-header.js` 的 `'use strict'`；更早的文件在**加载期**就调用后面文件里定义的函数，靠的是同一作用域里的函数提升）。拆成 45 个 script 单独加载会分别报 `Unexpected end of input`（开括号在 00-header、闭括号在 99-init）和 `hash2 is not defined` 之类。

所以：**IIFE 的括号由 `build.js` / `tools/devbundle.js` 补，源码文件里不要再自己写**；要直接跑就走 `dev-bundle.js`。

## 架构约定

所有 `src/js/*.js` 按清单顺序拼进**同一个 IIFE**，因此：

- 顶层 `function` / `const` **全局共享**，命名必须唯一；跨文件调用靠函数提升，无需 import。
- 文件顺序 = 依赖顺序（数据 → 核心 → 系统 → 渲染 → UI → 初始化），`init()` 只在最后一个文件调用一次。
- 不使用 ES module / TS / 任何运行时依赖，保证 `file://` 直接打开可用。

| 文件 | 职责 |
|---|---|
| `00-header` | IIFE 开头 + `use strict` |
| `10-const` `11-decor-data` `12-changelog` `13-achievements` `14-tasks` `15-crops` `16-recipes` | 常量与数据表（纯数据，无副作用） |
| `20-audio` `21-particles` | WebAudio 合成音效、粒子系统 |
| `30-state` | `newState()` / `getTile` / 绘制排序 |
| `31-save` | 3 槽位序列化、旧档迁移（v81 → v90） |

### 关键数据流

- `state` 是唯一真相；`serialize()` 显式挑字段落盘，`unpackState()` 缺字段回落到默认值（因此旧档可直接读）。
- 三槽位：`iso_farm_v9_slot_{1,2,3}` 各存一份完整状态，`iso_farm_v9_current` 记当前槽位；`iso_farm_v8_0` 会自动迁移进槽位 1。
- 挂机收益用**墙钟时间**结算（`state.idle.lastAt` + 分位小数），所以切后台、rAF 被冻结、乃至关掉页面后重开都能补上；作物同理：主循环对 `rawDt > 2s` 的部分按 `OFFLINE_RATE`(0.4) 补算，离线按 `OFFLINE_CAP`（8 小时）封顶；**挂机收益另有一个更小的 `IDLE_OFFLINE_CAP`（2 小时）**。
- 任务奖励不再是金币，而是普通肥料 / 高级肥料（`TASK_POOL[].reward`），高级肥料直接催熟。

## 玩法与数值

**核心循环**：锄地 → 播种 → 浇水/施肥 → 收获 → （收进仓库）→ 卖掉或拿去厨房做菜。

| 作物 | 种子 | 售价 | 收获次数 | 整周期 | 净利 | ROI | 金/秒 |
|---|---|---|---|---|---|---|---|
| 🥕 胡萝卜 | 4 | 10 | 1 | 36s | 6 | 250% | 0.167 |
| 🥬 白菜 | 5 | 13 | 1 | 42s | 8 | 260% | 0.190 |
| 🥔 土豆 | 6 | 16 | 1 | 54s | 10 | 267% | 0.185 |
| 🌾 小麦 | 8 | 18 | 1 | 66s | 10 | 225% | 0.152 |
| 🍚 水稻 | 10 | 30 | 1 | 90s | 20 | 300% | 0.222 |
| 🌽 玉米 | 12 | 34 | 1 | 78s | 22 | 283% | 0.282 |
| 🌶️ 辣椒 | 16 | 7 | **6** | 88s | 26 | 263% | 0.295 |
| 🍅 西红柿 | 20 | 8 | **6** | 89s | 28 | 240% | 0.315 |
| 🍆 茄子 | 26 | 11 | **5** | 96s | 29 | 212% | 0.302 |
| 🍓 草莓 | 26 | 5 | **10** | 99s | 24 | 192% | 0.242 |
| 🎃 南瓜 | 26 | 52 | 1 | 90s | 26 | 200% | 0.289 |

（整周期 = 首熟 `stageMs×3` + 复熟 `regrowMs×(收获次数-1)`；金/秒 = 净利 ÷ 整周期。）
- 一年生作物每次收获都要重新开垦；**多次收获作物**种一次收 N 次，每次复熟只要 `regrowMs`，地里会显示剩余次数小圆点。
- 起步推荐 **白菜**（5 金种子、42s 一轮）——开局 50 金能连种好几轮；**水稻** ROI 最高；**玉米/南瓜**是单次收获里的高收益档；**草莓**（10 轮）与辣椒/西红柿/茄子胜在**点击效率**（种一次管一季，不用反复开垦），把操作时间省下来。
- **浇水免费 ×2**，永远该浇；**普通肥料 ×1.5 且要花钱**，在已浇水的情况下基本是亏的（只在每日任务里划算）——数值设计上把肥料定位成"任务道具 + 应急加速"，而不是必买项。
- 收获时地块会回到荒地（一年生），这是刻意的节奏设计。
- **小麦不可切块**（`CROPS.wheat.noChop`）：切菜板会拒绝整颗小麦，提示「要拿去石磨磨面」；小麦（18）→ 面粉（**30**，与水稻同价）→ 面包（**60**）是它的正确去向。
- **多轮作物的售价按轮数定**：轮数只有 5~6 轮时，单价压太低会让它们不如单次作物，所以辣椒/西红柿/茄子回调为 7/8/11（种子 16/20/26）。改这类数值前先看 `cropRate()`。

### 扩建（v9.1）

**整块岛就是耕地**：开局只有 **3×3**，买一个面 → 4×3，再买另一个面 → 4×4。

- 点侧栏 **💰 扩建** 进入**扩建模式**：地图上出现 4 条发光长条（各自带价格），**点哪条就买哪条**；小人不会走过去（那些位置本来就不在当前岛内）。再点一次按钮或按 `Esc` 退出。
- 单价 `10 × 1.5^该方向已买次数`，**每个方向单独计数、单独封顶 1000**（右下买贵了不影响右上）；长条按买得起/买不起显示绿或红。
- **买来的地是草地且长满杂物**：灌木/石头/花/树随机分布（按坐标 hash 决定，可复现），用锄头一锄既清掉它、又顺便开垦那一格。
- 清出来的杂物进装饰仓库，可以**卖钱**（买回来是卖出去的 2 倍价），所以早期扩建基本能靠清理回本。
- **左上 / 右上各最多再扩 3 排可耕地**；达到上限后，这两个方向每次买到的变成 **3 排石头地面**——不增加可种植地块，但**可以布设装饰**（装饰品的专属场地）。
- **右下 / 左下（画面下方两向）没有上限**：可以一直买下去，每次都新增一排**可开垦的草地**（不会再被换成石头地）。价格仍按每方向独立 ×1.5 递增、1000 封顶，所以经济上自己会收敛。
- 只有**左上 / 右上**有上限：各自最多再扩 `UP_PLANT_LIMIT`(3) 排可耕地，之后每次买到的变成 **3 排石头地面**（不能种、只能布设装饰）。
- **老存档归一 · 上方石头带（v9.11）**：`normalizeTopStone(st)` —— 从农场左/上边界往外走，**只要那一列/行里确实有石头就补成整列/整行的石头**（`v9.8` 之前的扩建会在石头带里留下草地洞）；没有石头的普通草原不动；带装饰的石头格保留；农场范围内的空置石头格还原成草地。
- **老存档归一 · 下方石头地（v9.6）**：`unpackState` 里带 `normalizeOldLowerStone(st)` —— 旧版本在下方两向超过 14 排后给的是石头地面，读档时会把「农场右/下边界外那片石头」还原成**草地 + 杂物**并并入农场（当初买过的地不用再买一次）。两条红线：**顶部石头带不动**（`gx < farm.x0 || gy < farm.y0` 一律跳过）、**有装饰的格子不动**（那是玩家自己摆的展示区）。存档带 `SAVE_VER`（当前 95），迁移只跑一次，写档时用同一个版本号。
- 农场外的普通草地不能开垦（否则扩建没意义）；拿锄头点它可以把上面的装饰物收回仓库。
- 开局赠送 2 朵花 + 1 丛灌木 + 1 棵树（放在装饰仓库里，等开出石头地面就能摆）。

### 交互（v9.1）

| 操作 | 行为 |

| 作业期间点地图 | **取消**框选作业（非 UI 区域任意点击）；做完后选区自动收起 |
| 单击长条（扩建模式） | 购买那一面的扩建，长条与价格就在地图上 |
| 平移工具 ✋ | 拖动镜头，桌面端指针变抓手（会停止自动居中） |
| 缩放 🔍 / 滚轮 | 侧栏按钮循环 **自动 → 1x → 2x → 5x → 10x**；滚轮可微调（Ctrl+滚轮留给页面缩放） |
| 自动居中 | 平时农场始终在屏幕正中；手动平移或缩放后停止跟随，切回「自动」恢复 |
| 缩放观感 | **所见即所得**：放大时瓦片纹理与地面点缀一起放大（不做反缩放补偿）；自动倍率封顶 1.6x |

### 手机布局（v9.4）

手机端 `--ui-scale` 会被压到 **0.6**，所以 `calc(10px*0.6)` 只有 6px —— 关键尺寸一律用 `max()` 兜底，并且位置由一条**变量链**统一推导，改一个数不会互相打架（都在 `v9.css` 的竖屏媒体查询里）：

```
--m-edge            屏幕边距                        max(6px, 8px*scale)
--m-hud-h           顶栏高度（含内边距）
--m-toolbar-btn     工具栏按钮高度                  max(46px, 48px*scale)   ← 手指点得到
--m-toolbar-h       工具栏总高（含内边距）
--m-toolbar-bottom  工具栏离底                      max(12px, 18px*scale) + safe-area-inset-bottom
--m-hint-bottom     工具提示条底部 = 工具栏底部 + 工具栏高度 + 8px          ← 紧贴工具栏上沿
--m-toast-bottom    飘字底部 = 提示条底部 + 44px
--m-bottom-reserve  屏幕底部「别放东西」的高度 = 飘字底部 + 34px
```

- **工具提示条 / 飘字**：按文字**自适应宽度**（不再横贯整屏），提示条贴住工具栏，飘字在它上方；手机上字号 ≥11px / ≥12px。
- **右侧按钮栏（侧栏）**：位置由 `66-sidepanel.js` 的 `sidePanelBounds()` 统一算——上界 `max(10px, 顶栏下沿+10)`，下界 `提示条上沿 - 10 - 面板高度`；手机默认落在区间的 **0.62** 处（原来正中央，正好压住农场右半边）；拖动时同样被这两个边界夹住。`max-height` 扣掉顶栏与 `--m-bottom-reserve`，装不下时可内部滚动。
- **老存档**：侧栏位置带 `SIDE_PANEL_VER`（当前 2）。布局改了但存档里的 `sidePanelY` 是旧布局算的，所以版本不匹配时会**重算一次默认位置**，之后用户拖到哪记到哪。
- **刘海屏**：`viewport-fit=cover` + `env(safe-area-inset-*)`，顶栏避开刘海、工具栏避开 home 指示条。
- **触屏滚动**：`body` 原来是 `touch-action:none`，会把所有触摸滚动一起禁掉（成就/公告/仓库这些长列表滑不动）；现在 `body{touch-action:manipulation}`，手势交给 `canvas{touch-action:none}` 兜住。
- 改手机布局时，`tools/smoke.js` 里有对应的 CSS 断言（含变量链、字号兜底、`env()`、`touch-action`、`sidePanelBounds` 的边界来源），改坏了会在两个产物上都报错。
| 网格按钮 | 按钮上直接显示「开/关」，不再靠高亮颜色猜状态 |
| HUD | 一行只放关键信息（金币/两种肥料/成就/公告）；点 **⋯** 展开挂机速率、当前时刻、农场尺寸 |

### 厨房（拖拽 + 点选）

**版面（v9.18）**：顶部左「🧺 食材」右「🍽️ 菜品」（各半、各自内部滚动）→ 下方两行缩略工位：**备料行**（切菜板 / 石磨 / 拉磨的驴 / 自动切块机）与**烹饪行**（锅 / 烤箱）。每行左侧一个小 ▶ 按钮把原来的详细界面展开在下方（`.k-expand.open`，状态存 `state.kExpand`）。缩略卡的计时画成**绕边框的四段**（上→右→下→左，`kSetRing()` 设置每段的 `scaleX/scaleY`，`data-tone` 决定颜色），所以一张卡同时能表示「走到哪」和「是精品还是焦糊」。

食材货架 🌟 收藏优先，其余按数量倒序；拖到工位，**也支持「单击选食材 → 连点工位」快速投料**（手机友好）：

| 工位 | 投入 | 产出 | 判定 |

| 石磨 | 小麦 ×1 | 面粉 ×1（22 金） | **点一下立刻出 1 份**（和切菜板一个操作）；卡上「磨 ×N」= 一把最多磨 5 份 |

- 进度条三段刻度：**可收（绿 · 33%）/ 精品结束（金 · 50%）/ 焦糊（红 · 最右端 100%）**；`kSegTicks()` 生成，别再把焦糊刻度放到 50%。
- 厨房面板**分块对比重建**：`kPatchNodes()` 逐块比较 `.k-wrap` 的子节点，HTML 一模一样的直接保留旧 DOM；顶部两栏标了 `data-patch-group="top"`，所以放入食材**不会连坐重画右边的菜品仓库**，图标不闪、滚动不跳。

- 锅按配料多重集识别名菜：地三鲜 / 麻辣茄条 / 咖喱饭 / 什锦炒饭 / 红烩土豆 / 田园浓汤 / 普罗旺斯炖菜。
- **经济**：菜块价值 = 作物售价 × 0.40；杂烩 ×1.10、名菜 ×1.50~1.60、精品 ×1.5、焦糊 ×0.5。
  「1 颗胡萝卜（10 金）→ 3 块 → 杂烩 13 金 / 精品 16 金」≈ **1.3~1.6 倍**，不再出现"切一下煮一下就翻好几倍"的失衡；名菜要凑齐多种作物，约 1.8 倍。
- 设置里可关闭「厨房火候小游戏」，关闭后一律按正常出锅。
- 商店买卖装饰品（买价 / 回收价）：🌸花 12/6 · 🌿灌木 18/9 · 🪨石头 24/12 · 🌳树 32/16 · 💧水塘 70/35 · 🍄蘑菇 10/5 · 🌻向日葵 16/8 · 🪵木栅栏 12/6 · 🎋竹子 26/13 · 🌲松树 40/20 · 🏮石灯笼 60/30 · ⛲水井 90/45 · 🗿石像 150/75。卖出在 **🏡 装饰仓库** 里每行的「卖1 / 全卖」；石灯笼夜里自动亮灯。
- **对齐 vs 错落**：`placeDecor()` 摆出来的（小路/椅子/桌子/水井/石像…）一律**对齐格子**（`ox=oy=0`、`wild=false`）；只有 `scatterWeeds()` 自然撒出来的（草/石/花/树/蘑菇/竹子/松树/向日葵）才带随机偏移（`wild=true`）。判定见 `decorIsWild(d)`：装饰对象上的 `wild` 标记优先，老存档按 `DECOR_NATURAL` 类型推断并在读档时把人工装饰的偏移归零。`decorOffsetFor(type, h1, h2, wild)` 是唯一入口。
- 新增加了 `tools/decorshot.js`：把所有装饰 + 小路五个连接档画成总览图（人眼核对画法用）。
- **铺装（`ground + pave`）一共 6 种**：碎石小路 `path`、红砖路 `brick`（这两种是"成条的路"，有连接面）＋ 红/青/玉三色瓷砖与大理石（`full: true`，铺满整格、不需要连接）。画法：`drawPath`（土基 + 碎石子）/ `drawBrick`（错缝砖）/ `drawFullPave`（2×2 分块 + 勾缝 + 釉面高光，大理石多两道石纹）。
- **连接只认同材质**：`pathRawMask(gx, gy, type)` 里 `n.type === type` —— 碎石接碎石、红砖接红砖；不同材质之间要靠手动档位（`d.conn`）搭桥。
- **铺装是要买/任务拿的物品**（`DECOR_FREE` 现在是空的）：买价 = 回收价 ×2（碎石小路 6、红砖路 10、三色瓷砖 14/14/18、大理石 26），每日任务里有 4 个直接送地砖（见 `TASK_POOL` 里 `reward.decor` 那几条）。摆放扣仓库、敲掉收回，`placeDecor` 里 `meta.pave` 会记 `trackAction('pave')` 供「铺 N 块」任务判定。
- **装饰分两层**（`decorLayer(type)`）：`ground`（地砖/水塘，看 `DECOR_META[type].ground`）与 `prop`（树/椅子/栅栏…）。`decorAt(gx, gy, layer)` 按层查，不传层时**优先返回 prop**（锄头先敲立体层）。`canPlaceDecorAt(gx, gy, type)` 是唯一的放置判定：同层不能叠；**地砖只能盖在「玩家自己摆的」prop 之下**（`decorIsWild(prop)` 为真时提示先清杂草）；耕地/有作物一律拒绝。渲染时同格 `depth` 给 ground 减 0.001，保证地砖在下。
- **连接系统是通用的**（`connect: 4 | 8`）：栅栏是 8 向（`CONN8_MODES`：自动 / 八向全连 / 四向十字 / 四个斜角 / 横向 / 纵向 / 单点），小路与红砖路是 4 向（`PATH_CONN_MODES`）。`connDirs(type)` 决定方向表，`connMaskOf(d)` 统一算 mask（手动 `d.conn` 优先、邻居要愿意接过来），`cyclePathConn()` 点已有装饰换档。：`placeDecor` 不扣仓库、不看库存，随便刷；`collectDecorationAt` 不进仓库、`DECOR_SELL.path = 0`、也不进商店，避免「免费放 → 锄起来卖钱」的循环。
- **小路连接纹理**：`pathConnMask(d)` 按四邻算连接面（四位 1=上 2=右 4=下 8=左），手动 `d.conn` 优先，而且**邻居也得愿意接过来**（手动改过的一侧不会被硬接）。`drawPath(g, px, py, seed, mask)` **所有形状先按格坐标画再投影**（`P(dx,dy) = px + (dx-dy)*hw, py + (dx+dy)*hh`）—— 等距视角下按屏幕横竖画会变成阶梯。点已有小路 = `cyclePathConn()` 换档：自动 → 十字 → 横向 → 纵向 → 单点。

  - **云朵精灵**：`atmCloudSprite(i, c, rgb, a)`（rgb 量化到 8 一档，夜色变化才重烧）
  - **可见范围遍历**：`visibleGridRect(cx,cy,pad)` + `shVisibleTiles()`，阴影/地面细节/外沿不再全表遍历
  - 设置项 `showCropBars`（作物进度条开关）：`tileLOD()` 按「屏幕格子宽」分三级（≥34px 全细节 / ≥30px 减半 / 更小只留底色），`renderZoom` 由 `render()` 每帧写入；框选覆盖层用**一条平行四边形**（`iso(ax-0.5, ay-0.5)` 取外轮廓）代替逐格菱形，且 `jobBox` 期间**只描边**。量法见 `tools/perf.js`。
- **锅的聚合显示（v9.27）**：`kPotChipsHTML()` 按种类出一个 chip + `×N` 角标（节点数与块数无关）；`kPotSig()` / `kPotRecipeCached()` 让每帧刷新不再遍历上千元素；`potRecipe()` 的 `pieces` 是**去重种类表** + `counts`（主键与存档不随块数膨胀，价钱不变）；自动补料用 `potAddMany()` **一次写盘**（`potAdd` 逐块 save 是"越加越卡"的真凶）。
- **机器料斗（v9.19）**：驴 / 切块机各有独立进料槽（`state.autoSlot`，最多 `AUTO_SLOT_MAX`=5，空了自动从仓库补），互不抢料。
- **机器可停（v9.23）**：`autoPause(id)` / `autoResume(id)`（`state.autoPause`，0 = 在跑）。停着不产出、不吃料，**租期冻结**（恢复时把停的那段时间补回 `autoUntil`）。
- **长按持续添加（v9.23）**：`kRepeatArm(station)` → 420ms 后每 170ms 投一次（`kRepeatOnce`），缺料/满格自停；真拖动时 `kRepeatStop()` 让位给拖拽。
- **切后台补算（v9.23）**：`catchUpAway(ms)` 用**墙上时间**（不是 `performance.now()` —— 手机挂起时它不走）算离开时长；≤10 分钟全速、更久按 `OFFLINE_RATE`；厨房按 ≤1s 步长推进，`awayCatchUp` 期间不播音效/不写档。
- **环形进度（v9.19）**：`conic-gradient` + `mask-composite` 描边（贴着圆角走，`--p` 0~1），不支持时退回四段 `scaleX/scaleY`。
- **自动烹饪（一个开关管两件事，v9.18 起改名）**：UI 上就写「自动烹饪」；勾上后既**在精品窗口结束时自动取出**（`dur + perfect`，品质为「一般」），又**自动按同一配方补料**，直到那样原料不足才自己关掉；**手动取出随时可用**，那个时刻在精品窗口内就是精品。
- **手动磨粉是瞬时的**：`millLoad()` 把小麦装进石磨（最多 `MILL_CAP`=5 份，从仓库扣），`mill()` 一把全磨完；`KITCHEN.mill.busy/t/dur` 现在只是「自动磨面」进度条的显示状态（由 `autoTick` 写入）。`resetRuntime()` 会 `millUnload()` 把待磨的小麦退回仓库。
- **烤箱槽位升级**：`state.ovenSlots`（1~`OVEN_SLOT_MAX`=6），`ovenSlotPrice()` = `2000 × 1.5^(slots-1)`；`KITCHEN.oven.items` 是原料数组，满槽才拒绝，出炉一次全出且品质一致；每放一份会重置火候计时。
- **全自动（同配方循环）**：勾上后按**同一个配方**自动投料 + 自动取出，直到那样原料不足才停（`autoLoopFeed()` 用 `ovenPut(lastItem, true)` 的 **strict** 模式 —— 只认同一配方，不会抓别的原料顶上）。`lastItem`/`lastPieces` 在 `ovenPut`/`potAdd` 里记录。
- **限时自动化设备**（`AUTO_DEVICES`，金币购买、到期自动停、**可叠加**）：🐴 拉磨的驴 600 金/5 分钟（小麦→面粉）、🔪 自动切块机 900 金/5 分钟（切库存最多的作物）；每种最多 `AUTO_MAX`=5 台，第 n 台价格 = `price × 1.6^n`（`autoPrice()`），**每轮每台产 1 份**。开着厨房面板时产出会出声（`kKitchenOpen()` 判断）。到期时间存 `state.autoUntil`，进度累加在 `state.autoAcc`，逻辑在 `autoTick(dt)`（随 `kitchenLogicTick` 每帧跑）；还在跑时再买会顺延。

### 存档迁移（v9.21，纯前端 · 不需要服务器）

入口：**💾 存档槽位 → 📦 存档迁移**。三种载体，**都不依赖任何后端**：

| 载体 | 怎么送到新手机 | 大小 |
|---|---|---|
| `.farm` 文件 | 微信「文件传输助手」/ AirDrop / 网盘 | 无上限 |
| 存档串 | 微信/短信直接粘贴（`FT1:` 开头） | 实测开局 ~1.3KB、11×11 ~2.2KB、32×32 ~5KB |
| 自包含链接 | 发链接，对方点开就弹导入 | 同上（fragment 不进服务器日志） |

- **加密**：`PBKDF2(pin, salt, 600000)` → `AES-GCM`；密文里**看不到明文**。密码**不写进文件**，导出时输两次（输错就真打不开）。
- **信封**：`FT2:` + 紧凑二进制（`FT` 头 · 版本 · flags · 迭代下标 · salt16 · iv12 · 密文，**只 base64 一次**）；`FT1:`（v9.21 的 JSON 信封）仍能解码。实测 20×20 农场：3.8KB → **2.8KB**（-27%）。
- **密码框**不是 `type=password`（免得被密码管理器当成账号密码），是 text + `inputmode=numeric` + `autocomplete=off` + `-webkit-text-security:disc`。
- **二维码**：整档装不进去（QR byte 模式上限 2953B、好扫 ≤1.2KB），`tfQrFit()` 会如实判断并说明；二维码留给「8 位短码」。
- **自包含链接**能离线工作，是因为 `#s=` 是 URL fragment —— 浏览器**不会**把它发给服务器，页面自己读 `location.hash`（`tfParamPayload()`），所以"发链接"这件事本身也不需要后端。
- **导入体检** `tfSanitize()`：地块 ≤ `TF_MAX_TILES`(2 万)、坐标必须有限整数、作物/地形/状态白名单、金币/肥料夹上限、装饰 ≤ 5000；脏数据清洗后 `unpackState()` 才落地。
- **写盘**：`tfWriteSlot()` 先把目标槽原内容存成 `slot_N.bak`，再把 `savedAt` 归到现在（避免一导入就弹「离线 30 天」）。
- **保命**：启动 `tfPersistStorage()` 申请持久化 + iOS 7 天清档提示；`save()` 写失败会提示一次（`saveWarned`）。

### 🤖 自动农活（v9.28）

侧栏「🤖 自动农活」→ 框一块地（`AF_AREA_MAX`=12×12）+ 勾选轮作步骤（耕地/播种/施肥/收获）+ 点选种子顺序轮作。

- **谁干**：**小人自己**（复用 `p.queue`，`afPlanPass()` 按 耕地→播种→施肥→收获 收集格子，`planPath()` 走近路）；队列空了 `afTick()` 自动排下一趟（`AF_RETRY_MS`=700ms 防重排）。
- **步骤顺序**：`AF_STEPS` = 耕地 → 播种 → 施肥 → 收获 → **浇水**（水放最后：地大了前面刚种后面就熟，最后一遍走完不用折返）。
- **代价**：**每完成一个方块的动作扣 1 点饱食度**（耕地/播种/施肥/收获/浇水都算；在 `updatePlayer` 里 `op.auto` 的操作完成后调 `afOnWorkDone()`）。
- **肥料自动买**：`state.autoFarm.buyFert` 勾上后 `afEnsureFertilizer()` 按需补货（`FERT_COST` 金/份、单趟 ≤ `AF_BUY_FERT_MAX`=20、没钱不买、不会负金币）。
- **显示**：菜单顶部大字条 + 侧栏按钮 `🍚N` + 地图区域标签 `🤖 3×3 · 🍚12`。
- **饱食度**：`afDishSatiety()` = 材料块数 × `AF_SAT_PER_MATERIAL`(10) × 品质系数（`QUALITY[x].mult`）。**只有成品菜算**（原材料/菜块/面粉不算）。
- **预备口粮**：`state.autoFarm.ration` 勾选哪些菜可以吃；`afRationOK()` 拒绝价值 > `AF_RATION_MAX_VALUE`(2000) 的菜；`afEatOne()` 先吃点数少的（`afRationList()` 排序），饿了自己吃。
- **停机**：没口粮/没种子/没肥料/没框地 → `afStop()` 写明原因并清掉队列；因缺料被 `queueStopMsg` 就地停手时也会一起停（`afStop(stop, true)`）。
- **只在线跑**：切后台不结算（离线平衡先不碰）。

### 挂机收益

`0.3 金/分 + 0.06 金/分 × 已解锁成就数`（30 个成就拉满 **≈2.1 金/分 ≈ 126 金/小时**），离线只结算 **2 小时**（`IDLE_OFFLINE_CAP`，与作物补算的 `OFFLINE_CAP` 8 小时是两回事）；HUD 上 `💤 x.x/分` 实时显示。定位是**保底零花**：离线 2 小时 ≈ 250 金，明显低于种田/做菜，挂机压不过手动。

### 昼夜与天气

一天 **22 分钟**真实时间：**清晨 2 + 白天 10 + 傍晚 2 + 夜晚 8**（分段推进小时，夜长昼短），影响环境光、太阳方位与阴影长度；天气在晴 / 多云 / 雨之间轮换。`state.clockMs` 会存档。

**雨天是持续湿润**：不只在下雨那一刻浇一遍 —— 雨中新种下的、多次收获复熟后 `watered` 被重置的，都会立刻自动喝饱水（`applyRainWatering()` 每帧检查，只有第一次会弹提示）。所以下雨期间玩家完全不用碰水壶，框选浇水也会因为「没有需要浇水的作物」自己跳过（返回 0 格、不排作业）。

## 加东西的姿势

- **加作物**：往 `15-crops.js` 的 `CROPS` 加一项（`harvests` + `regrowMs` 即多次收获），再往 `SEED_ORDER` 加 id；如需专属外观，在 `44-food-art.js` 里加画法（`drawCrop` 会自动派发，缺省走通用幼苗）。
- **加菜谱**：`POT_COMBOS` 加 `need`（配料多重集）+ `factor`；或在 `DISHES` 里加固定产线。
- **加成就 / 任务**：`13-achievements.js` 的 `ACHIEVEMENTS`（`cond(state.stats)`）、`14-tasks.js` 的 `TASK_POOL`（`type` 需在 `trackAction` 里已有对应分支，`reward` 用 `{fert:n}` / `{premium:n}`；`hard:true` 标困难，`need:'mill'|'cook'|'expand'|'premium'` 加解锁门槛）。
- **加装饰**：`11-decor-data.js` 加一项（`price`/`sell`，如果可被锄头敲掉再给 `hp`），画法加到 `42-decor-art.js` 的 `drawDecor`，商店列表来自 `DECOR_IDS`。
- **调试入口**：浏览器控制台里 `FarmDebug.state` / `FarmDebug.api`（含 `applyToolAt`、`step(ms)`、`cook.*`、`kitchenTick`、`idleAdvance`、`saveToSlot/loadSlot`、`setAtmos(hour,weather)`、`fx.*`）。

## 已知限制

- 厨房里正在烤/正在煮的东西**不存档**（重开页面会清空），避免"离线回来一堆烤糊的面包"。
- 只有一口锅、一个烤箱、一个石磨；没有厨具升级/扩建。
- 装饰物只影响观感（会占住地块，需锄掉才能种），没有加成。
- 没有音效资源文件，全部是 WebAudio 现场合成的方波/正弦音。
- 移动端可用（Pointer Events + UI 缩放），但没有做横竖屏专门布局。
